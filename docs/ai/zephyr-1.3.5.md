# Android 1.3.5：OpenRouter 长输入排查

修复模型参数页“更新当前模型的已知参数能力”无条件清空参数的问题。更新后保留仍受支持的无思考、速度等选择，只剔除失效参数。OpenRouter 参数页增加显式关闭思考按钮；不会擅自切换提供商或覆盖其他参数。

此前清空 `reasoning_effort=none` 后，请求不再发送 `reasoning.enabled=false`。2026-11-10 官方模型列表标明 DeepSeek V4 Flash 0731 的默认推理状态为开启，默认强度 high；这是一条可能导致延迟升高的代码路径，尚不能证明是报告中手机超时的唯一原因。

请求超时现在区分排队、DNS、连接、TLS、发送、等待响应和接收结果；所有阶段仍受原有总超时限制，无自动重试。Policy 的样例页增加 100 字符合成输入按钮，发送时使用该 Policy 的实际配置。

电脑合成请求实测：相同 DeepSeek / wafer/us 路由，显式无思考，输入 10 / 100 / 200 字符分别约 561 / 921 / 1139 ms，reasoning_tokens 均为 0。电脑结果不能代替 S26 的网络和当前配置验证。

官方能力来源：https://openrouter.ai/api/v1/models 与 https://openrouter.ai/api/v1/models/deepseek/deepseek-v4-flash-0731/endpoints 。

验证完成：37 项共享核心测试、27 项模拟器回归通过。首轮回归的原有分词测试在编辑器初始化阶段丢失一次首字母；未修改断言，完整复跑 27 项通过。

Android 模拟器直接连接 OpenRouter（非代理转发），DeepSeek / wafer/us / 无思考，10 秒总超时：100 字符 2615 ms，200 字符 643 ms，均返回单个合法候选。此为两次测量，不代表稳定的平均延迟；100 字符首请求可能包含连接建立成本。测试凭据通过一次性本地 TLS 仅加载到内存，未存入 APK、项目或应用配置。

ARM64 demo APK 已构建并检查打包资源；按用户要求未进行 S26 验证。无法证明原手机超时的唯一原因或保证其网络上的延迟。
